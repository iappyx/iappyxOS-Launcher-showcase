Microsoft 365

Surface Outlook mail, Calendar, To Do, OneDrive, OneNote, and Excel ranges in widgets and wallpapers. Microsoft uses OAuth, so the one-time setup is a few steps — after that it auto-refreshes itself.

How to get a Client ID + Refresh Token (one-time, ~5 min)
  1. Open portal.azure.com → App registrations → New registration. (Free, works with any Microsoft account — no Azure subscription needed.)
  2. Name: anything (e.g. "iappyxOS Launcher"). Supported account types: "Accounts in any organizational directory and personal Microsoft accounts (Multitenant + personal)". Leave the redirect URI blank for now.
  3. Once created, copy the Application (client) ID from the Overview page.
  4. Go to Authentication → Add a platform → Mobile and desktop applications (NOT "Web" — Web requires a client_secret). Tick http://localhost in the list of suggested URIs, then Configure.
  5. Go to API permissions → Add → Microsoft Graph → Delegated. Add: offline_access, User.Read, Mail.Read, Calendars.Read, Tasks.Read, Files.Read.All, Notes.Read.All. Personal-account-only — no admin consent needed.
  6. Open this URL in a desktop browser (replace YOUR_CLIENT_ID):
    https://login.microsoftonline.com/common/oauth2/v2.0/authorize?client_id=YOUR_CLIENT_ID&response_type=code&redirect_uri=http%3A%2F%2Flocalhost&response_mode=query&scope=offline_access%20User.Read%20Mail.Read%20Calendars.Read%20Tasks.Read%20Files.Read.All%20Notes.Read.All&prompt=consent
  7. Sign in and approve. Your browser redirects to http://localhost/?code=M.C5_…long-code…. The page will fail to load — that's fine; just copy the code value from the URL bar.
  8. From a terminal, exchange the code for a refresh token:
    curl -X POST https://login.microsoftonline.com/common/oauth2/v2.0/token -d grant_type=authorization_code -d code=THE_CODE -d redirect_uri=http://localhost -d client_id=YOUR_CLIENT_ID -d scope='offline_access User.Read Mail.Read Calendars.Read Tasks.Read Files.Read.All Notes.Read.All'
  9. The JSON response includes refresh_token. Paste it below.

Got AADSTS70002: client_secret required? The redirect URI is registered under the Web platform instead of Mobile and desktop applications. Azure treats Web as a confidential client and demands a secret even with "Allow public client flows" enabled. Delete the Web entry from Authentication → Platform configurations and re-add the URI under Mobile and desktop applications.
